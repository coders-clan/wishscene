# Internationalization and RTL

The studio supports English, Hebrew and two test locales. Choose Language in the desktop header, phone More sheet or login page. A saved choice takes precedence over quality-weighted browser preferences, then English. The document language and direction are set on the server. Changing language reloads the page; when an editor has unsaved changes, a confirmation allows cancelling without changing the locale cookie or losing the draft.

## Catalogs and contributions

`apps/web/messages/{locale}/{namespace}.json` contains flat ICU MessageFormat catalogs. English is the source. The namespaces are `common`, `studio`, `mobile`, `feedback`, `auth`, `demo` and `metadata`. `messages/descriptions/{namespace}.json` provides context for each key. Translations come through GitHub PRs; a translation service is optional, not a runtime dependency.

Use whole phrases, ICU plural/select arguments and ICU number/date formatting. Preserve placeholder names across translations. Literal IDs, URLs, filenames, CSS classes, platform aspect ratios and user/generated content are data, not translation keys. Product and platform names remain recognizable. Feedback activities carry structured changes so current activities can render in the viewing locale; historical activity text without structured fields remains unchanged.

To add a language:

1. Copy `messages/en` to a new BCP 47 locale folder, such as `messages/pt-BR`, and translate every namespace.
2. Add the locale tag to `supportedLocales` in `src/i18n/locales.ts`. Its displayed name comes from `Intl.DisplayNames` in its own language; direction comes from `Intl.Locale` text information with a shared fallback.
3. Run `pnpm i18n:extract` to generate the catalog registry, translator descriptions and pseudo-catalogs. No component or request-loader edits are needed.
4. Run `pnpm check` and `pnpm test:e2e`. A deliberately incomplete locale must also be listed in `partialLocales`; missing entries then fall back to English. Get native-speaker copy review before release.

`en-XA` accents literal text and adds roughly 35% length. `ar-XB` applies RTL overrides to literals. Both preserve ICU arguments and plural behavior. Their selectors are available for development and review.

## Rendering and checks

Clients use `useCopy`/`useTranslations`; servers use `getTranslations`. `useFormatter` and ICU format values with the active locale. Dates use the explicit UTC request timezone, making server/client rendering deterministic. User text uses `dir="auto"` and bidi isolation; mixed-script interpolations are isolated. The font stack includes Hebrew, Arabic, CJK and Devanagari fallbacks, with system fallback for installed scripts.

Flat namespaces merge translated keys over English. Missing entries log warnings in development. API errors carry stable codes and are translated in clients. Document metadata, PWA manifest, accessibility labels, empty states and editor errors use the same catalogs.

Use logical CSS for app layout. Directional navigation icons mirror in RTL; logos, checkmarks and media controls do not. Galleries measure element edges rather than relying on RTL `scrollLeft` signs. Crop and annotation coordinates and exported artwork keep physical coordinates. Social preview and export share the localized disclosure; its physical left anchor is intentional.

`pnpm i18n:check` runs inside `pnpm check`. It checks ICU validity, placeholder parity, shipped catalog completeness, unused keys, generated registry/pseudo freshness, JSX copy and unmarked physical CSS. Centered overlays have inline geometry comments; image/canvas coordinates are separate from UI direction. Add translator descriptions when changing source copy, then run `pnpm i18n:extract`.

Tests cover negotiation, regional fallback, script direction, English key fallback/warnings, secure cookie writes, Arabic plural categories, localized numbers and pseudo ICU preservation. Playwright runs home/studio/feedback journeys in all four locales at desktop and phone sizes, plus unsaved-draft and RTL gallery regressions. Existing English tests cover full exports, crop gestures, feedback annotations, votes and stale edits.
